
# 💬 astrbot_plugin_context_compressor (无感压缩上下文)

可手动调用，异步处理压缩，触发条件更灵活的，翻版 AstrBot 官方上下文压缩个人用插件。

复刻 AstrBot 官方的压缩上下文功能，但是不会简单的 truncation 截断抹除历史，而是将老历史压缩后作为前情提要注入到新一轮的 context 中，保证核心线索不丢失。

和官方的判断条件不同，达到设定的对话轮数，**或**达到设定的最大 context token 数量，即自动进行压缩上下文。且可以通过 `/compress` 命令手动压缩上下文。

---

## 🚀 核心机制与性能优化点

### 1. 像素级对齐最大化前缀缓存（Prefix Caching）命中

大模型（如 Gemini / DeepSeek）的前缀缓存命中要求请求体顶部的 `systemInstruction`、`tools`（工具声明列表）以及控制超参数（如思维链配置、温度等）必须完全一致。
插件通过主管道拦截器，静默抓取当前主对话完全装配好的提示词、工具链和运行时超参数。在后台拉起总结任务时，作为参数全量镜像灌回。用完全相同的参数与长历史前缀投递总结请求，保证日常聊天和后台总结均能 100% 享受到前缀缓存的超低资费与极速响应。

### 2. 双管齐下的异步无感处理

当新到来的用户消息到达压缩阈值时，插件在消息入口不进行串行拦截。主对话拿着完整的全文 context 正常请求响应（此时历史未动，100% 命中缓存）。同时后台直接开辟独立的异步协程任务，一边静默等待当前这轮回复安全落库，一边并发发起另一个大模型总结请求。整个压缩后的新上下文会静静躺在数据库里，服务于下一轮对话，用户聊天完全感受不到卡顿。

### 3. 并发增量无损合流（Delta Patching）

后台模型总结需要大约 3 秒的网络窗口期。针对在此期间用户手快、连续发送新消息的场景，插件在最终回写数据库的瞬间，会自动重新打捞数据库并剥离出新产生的增量消息（Delta），动态将补丁续接在最近保留消息的最末尾，实现 0 丢包无损合流，防止历史快照覆盖新消息。

### 4. 内存防重叠锁与指数退避

面对连续高频发送，插件在内存中维护 CID 会话防重锁，确保同一会话同一时间只有一个总结任务在飞，拒绝重叠请求轰炸网关。针对并发落库时 SQLite 物理锁死冲突，引入指数退避重试，平滑排队写入，保证数据持久层稳定性。

### 5. 原生强类型对象流驱动

抛弃纯文本格式化和拼接，完全在官方 `Message` 强类型对象流中执行算子切片。无损保留历史记录中包含的富文本、多模态附件以及未处理完的工具调用状态（Tool Calls），配合官方标准的反序列化算子落库，规避接口因格式不合规抛错。

## ⚙️ 配置面板结构 (`_conf_schema.json`)

配置可以根据不同的大模型或者不同的平台机器人，组合设定具体的压缩参数配置。

* **全局基础水线**：触发总结的对话轮数（一问一答算 1 轮，默认 40）、触发 Token 阈值（默认 16000）、压缩后保留的最新原文轮数（默认 2 轮）。
* **个性化总结提示词指令**：分发给后台大模型的总结大纲要求。留空则自动使用内置的系统默认指令。
* **特异性个性化规则列表 (`special_rules`)**：
* `rule_name`: 📌 规则备注/别名（用于让用户在多条规则时一眼区分，如“QQ代码群”、“网页测试”）。
* `target_provider`: 匹配的当前会话大模型（数据绑定官方下拉菜单）。
* `target_platform_id`: 匹配的机器人实例 ID（手动填写文本，如 `qq_bot_01`）。
* `chat_type`: 匹配聊天场景性质（下拉菜单：留空不限、group群聊、private私聊）。
* `rule_summary_provider`: 专属负责压缩总结的大模型。若留空，插件将动态直接继承当前对话框所使用的大模型。
* `专属水线控制`: 允许针对特定节点重载独立的 `max_turns`、`max_tokens`、`keep_recent`。

## 🛠️ 安装方法

1. 下载本插件，将文件夹命名为 `astrbot_plugin_context_compressor`。
2. 放入你的 AstrBot 插件目录（`core/data/plugins/`）。
3. 重启机器人，在 Web 管理面板里启用它并填写参数即可。
